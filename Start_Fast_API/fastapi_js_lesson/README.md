# Занятие «FastAPI + JavaScript: от кнопки до JSON и обратно»

Готовый комплект на **90 минут** для учеников, которые уже знают функции, списки,
словари и основы FastAPI. В комплекте один проект для объяснения и три фронтенда,
для которых ученики пишут серверную часть.

## Результат занятия

К концу занятия ученик сможет:

- объяснить путь данных `браузер → HTTP-запрос → FastAPI → JSON → браузер`;
- получить данные через `fetch()` и `GET`;
- отправить JSON через `POST` или `PATCH`;
- принять тело запроса в модели Pydantic;
- вернуть правильный HTTP-статус и показать ошибку в интерфейсе;
- проверить контракт API через Swagger и `pytest`.

## Что лежит в папке

| Папка | Режим | Страниц | Тема сервера |
|---|---|---:|---|
| `00_demo_coffee_queue` | показывает преподаватель | 1 | GET, POST, PATCH, Pydantic |
| `01_task_board` | базовая практика | 1 | CRUD списка задач |
| `02_library` | средняя практика | 2 | поиск, query-параметры, избранное |

Во всех проектах фронтенд уже готов. Ученики работают в `main.py` и сверяются с
`TASK.md`. Автотест `test_api.py` проверяет не внешний вид, а договор между JS и
сервером: адрес, метод, статус и форму JSON.

## Подготовка преподавателя

Из этой папки:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

На Windows команда активации:

```powershell
.venv\Scripts\activate
```

Проверьте готовый пример:

```bash
cd 00_demo_coffee_queue
uvicorn main:app --reload
```

Откройте:

- интерфейс: <http://127.0.0.1:8000>;
- Swagger: <http://127.0.0.1:8000/docs>.

## Запуск Coffee Queue через Docker

Для запуска нужен только Docker, без Docker Compose. В учебных целях PostgreSQL и
FastAPI запускаются вместе в одном контейнере.

Перейдите в папку готового примера:

```bash
cd 00_demo_coffee_queue
```

Соберите образ:

```bash
docker build -t coffee-queue .
```

Запустите контейнер:

```bash
docker run --rm -p 8000:8000 coffee-queue
```

При запуске контейнер сам:

1. запускает PostgreSQL;
2. создаёт базу `coffee`, если её ещё нет;
3. создаёт таблицу `coffee_orders`;
4. запускает FastAPI на порту `8000`.

После запуска откройте:

- интерфейс: <http://localhost:8000>;
- Swagger: <http://localhost:8000/docs>.

Чтобы остановить приложение, нажмите `Ctrl+C`. Параметр `--rm` автоматически
удалит остановленный контейнер. При следующем запуске база будет пустой — это
удобно для повторения учебного примера с начала.

## План занятия на 90 минут

### 0–10 минут. Зачем фронтенду сервер

Покажите страницу кофейни и задайте вопрос: «Где хранится очередь, если обновить
страницу?» Подведите к разделению ролей:

- HTML задаёт структуру;
- CSS отвечает за вид;
- JavaScript реагирует на действия и делает запрос;
- FastAPI хранит данные, проверяет их и принимает решения.

Нарисуйте на доске один маршрут данных:

```text
нажатие кнопки
      ↓
fetch("/api/orders", { method: "POST", body: JSON.stringify(...) })
      ↓ HTTP + JSON
FastAPI → Pydantic → функция маршрута
      ↓ JSON + статус 201
await response.json()
      ↓
JavaScript обновляет DOM
```

Главная мысль: **JS и FastAPI не знают внутреннее устройство друг друга. Они
договорились только об URL, HTTP-методе и форме JSON. Это и есть контракт API.**

### 10–35 минут. Один пример вместе

Используйте `00_demo_coffee_queue` и сценарий из `TEACHER_DEMO.md`.

1. Выполните `GET /api/drinks` в Swagger.
2. Найдите такой же URL в `frontend/app.js`.
3. Поставьте `print(payload)` в `POST /api/orders` и создайте заказ из браузера.
4. Покажите соответствие JSON и `OrderCreate(BaseModel)`.
5. Отправьте пустое имя и обсудите статус `422`.
6. Отправьте неизвестный `drink_id` и обсудите `404`.
7. Отметьте заказ готовым, чтобы увидеть path-параметр и `PATCH`.

Не объясняйте весь файл сверху вниз. Каждый раз идите от видимого действия в
браузере к одной строке `fetch`, а затем к одному маршруту Python.

### 35–40 минут. Разбор задания

Разделите учеников по уровню или дайте всем `01_task_board`, а быстрым парам
предложите перейти к следующему проекту.

Порядок работы ученика:

1. запустить стартовый `main.py` и убедиться, что фронтенд открывается;
2. прочитать таблицу API в `TASK.md`;
3. реализовывать по одному маршруту;
4. после каждого маршрута проверить Swagger;
5. запустить `pytest -q`;
6. только затем нажимать кнопки во фронтенде.

### 40–75 минут. Самостоятельная работа

Рекомендуемый выбор:

- новичок: `01_task_board`;
- уверенный ученик: `02_library`;
- быстрый ученик или пара: `03_room_booking`.

Контрольные точки преподавателя:

- на 50-й минуте работает первый `GET`;
- на 60-й минуте работает создание через `POST`;
- на 70-й минуте ошибки возвращаются через `HTTPException`, а не как
  `{"error": "..."}` со статусом 200.

### 75–85 минут. Разбор решений

Попросите одного ученика показать путь одного объекта целиком:

1. объект создаётся в форме;
2. JS превращает его в JSON;
3. Pydantic проверяет JSON;
4. Python добавляет `id` и сохраняет объект;
5. сервер возвращает объект;
6. JS рисует его на странице.

Сравните два типа ошибок:

- `422` создаёт FastAPI, когда тело не подходит модели;
- `404` или `409` создаёт код ученика, когда данные формально верные, но действие
  невозможно.

### 85–90 минут. Exit ticket

Пусть каждый письменно ответит на три вопроса:

1. Зачем в `fetch` нужен `JSON.stringify()`?
2. Чем `response.ok` отличается от успешного `response.json()`?
3. Кто должен решать, можно ли забронировать занятую комнату: JS или сервер? Почему?

Ожидаемая мысль в третьем ответе: сервер, потому что интерфейсов и пользователей
может быть несколько, а правило должно работать для всех.

## Мини-шпаргалка для доски

### JavaScript отправляет JSON

```js
const response = await fetch("/api/orders", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ customer: "Маша", drink_id: 2 }),
});

if (!response.ok) {
  const error = await response.json();
  throw new Error(error.detail ?? "Ошибка сервера");
}

const order = await response.json();
```

### FastAPI принимает JSON

```python
class OrderCreate(BaseModel):
    customer: str
    drink_id: int


@app.post("/api/orders", status_code=201)
def create_order(payload: OrderCreate):
    return {"id": 1, **payload.model_dump()}
```

### Осмысленная ошибка

```python
raise HTTPException(status_code=404, detail="Напиток не найден")
```

## Частые ошибки учеников

| Симптом | Что проверить |
|---|---|
| страница открылась файлом, запрос не работает | запускать через Uvicorn, не двойным кликом по HTML |
| `Unexpected token` в JS | сервер вернул не JSON; посмотреть Network → Response |
| FastAPI вернул `422` | сравнить имена и типы полей JSON с моделью Pydantic |
| всегда приходит `200` | указать `status_code=201/204` и использовать `HTTPException` |
| после `DELETE` ошибка чтения JSON | при статусе `204` не вызывать `response.json()` |
| `/docs` работает, а UI нет | проверить URL в `fetch` и вкладку Network |
| API-маршрут даёт `404` | проверить, что декоратор, метод и адрес совпадают с контрактом |

## Оценивание, 10 баллов

- 2 балла: все обязательные GET-маршруты;
- 2 балла: создание через POST и модель Pydantic;
- 2 балла: изменение или удаление;
- 2 балла: правильные статусы `201`, `204`, `404`, `409`;
- 1 балл: понятные имена и отсутствие дублирования;
- 1 балл: все тесты проходят и интерфейс работает после обновления страницы.
