# Задание 3. Roomly — бронирование переговорных

Сложное задание на две страницы:

- `/` — выбор комнаты и создание бронирования;
- `/schedule` — расписание на дату и отмена брони.

Здесь недостаточно CRUD. Сервер обязан запрещать пересечение встреч.

## Запуск

```bash
uvicorn main:app --reload
```

## Исходные комнаты

```python
rooms = [
    {"id": 1, "name": "Фокус", "capacity": 2, "equipment": ["Монитор"]},
    {"id": 2, "name": "Спринт", "capacity": 6, "equipment": ["TV", "Маркерная доска"]},
    {"id": 3, "name": "Панорама", "capacity": 10, "equipment": ["Проектор", "Камера"]},
]

bookings: list[dict] = []
```

Формат бронирования:

```json
{
  "id": 1,
  "room_id": 2,
  "room_name": "Спринт",
  "employee": "Алина",
  "date": "2026-09-15",
  "start_hour": 10,
  "duration_hours": 2
}
```

## Контракт API

| Метод и URL | Тело | Ответ | Статус |
|---|---|---|---:|
| `GET /api/rooms` | нет | `{"items": [...]}` | 200 |
| `GET /api/bookings?date=2026-09-15` | нет | `{"items": [...]}` | 200 |
| `POST /api/bookings` | данные формы | созданное бронирование | 201 |
| `DELETE /api/bookings/{booking_id}` | нет | пустой ответ | 204 |

Тело POST:

```json
{
  "room_id": 2,
  "employee": "Алина",
  "date": "2026-09-15",
  "start_hour": 10,
  "duration_hours": 2
}
```

Используйте тип `date` из стандартного модуля `datetime`, тогда FastAPI проверит
формат даты сам.

## Правила

1. Офис работает с 08:00 до 19:00.
2. Встреча длится от 1 до 4 часов.
3. Встреча должна закончиться не позже 19:00.
4. Комната должна существовать, иначе `404`.
5. Бронирования одной комнаты в один день не могут пересекаться, иначе `409`.
6. Неизвестное бронирование при удалении возвращает `404`.
7. `GET /api/bookings` возвращает встречи по времени: сначала ранние.

## Как найти пересечение

Считайте интервалы полуоткрытыми: встреча с 10:00 на 2 часа занимает `[10, 12)`.
Следующую можно начать ровно в 12:00.

Два интервала пересекаются, если:

```python
new_start < old_end and old_start < new_end
```

Проверяйте только бронирования той же комнаты и даты.

## Модель тела

Начните так и добавьте ограничения `Field`:

```python
from datetime import date

from pydantic import BaseModel, Field


class BookingCreate(BaseModel):
    room_id: int
    employee: str = Field(min_length=2, max_length=40)
    date: date
    start_hour: int = Field(ge=8, le=18)
    duration_hours: int = Field(ge=1, le=4)
```

Если встреча заканчивается после 19:00, самостоятельно верните `422` через
`HTTPException` с понятным `detail`.

## Проверка

```bash
pytest -q
```

Обязательно проверьте руками:

1. создайте встречу 10:00–12:00;
2. попробуйте ту же комнату 11:00–12:00, ожидается конфликт;
3. создайте встречу с 12:00, она должна сохраниться;
4. выберите другую комнату на 11:00, она тоже должна сохраниться.

## Со звёздочкой

должны выполняться те же проверки, но сама изменяемая встреча не должна конфликтовать
